Three cooperating sub-packages with a clear dependency direction (domain layer depends on this module, not vice versa):
- `database/` — `DatabaseModule` is a `@Global()` NestJS module that registers the Drizzle `db` connection and `pool` from `@ananya/database` under string tokens `DATABASE_CONNECTION` / `DATABASE_POOL` (defined in `database.constants.ts`) so any feature module can consume them without importing the module.
- `infrastructure/repositories/` — one file per aggregate root (`drizzle-*.repository.ts`). Each class implements a repository interface exported by its owning domain package (e.g. `AccountRepository` from `@ananya/finance`, `CustomerRepository` from `@ananya/sales`) and uses Drizzle query builders from `@ananya/database/query` against typed schemas from `@ananya/database/schema`. Row-to-domain mapping is done via local `toDomain` helpers that call the domain entity's static `rehydrate` factory; persistence uses `insert().values().onConflictDoUpdate` for idempotent upserts, and multi-table aggregates (e.g. Customer → contacts + addresses) are loaded eagerly in `findById`/`findMany`.
- `common/logging/http-logging.interceptor.ts` — a Nest `NestInterceptor` that injects an `X-Request-Id` header, emits structured JSON access/error logs keyed by request ID, and is gated by `HTTP_ACCESS_LOGGING` / `HTTP_ERROR_LOGGING` env flags.
- `common/utils/postgres-error.ts` — utility to unwrap Drizzle/pg error chains (up to `MAX_CAUSE_DEPTH = 5`) and extract SQLSTATE codes (`23505` unique violation, `23503` foreign-key violation) for constraint-violation translation inside repositories.

Dependency direction is strictly outward: this module imports domain interfaces from sibling packages (`@ananya/finance`, `@ananya/sales`, etc.) but no domain code imports back into it.
