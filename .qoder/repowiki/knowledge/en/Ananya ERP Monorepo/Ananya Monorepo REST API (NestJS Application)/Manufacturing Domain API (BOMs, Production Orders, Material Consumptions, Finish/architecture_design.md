Each subdirectory is an independent NestJS `@Module` (`boms`, `production-orders`, `material-consumptions`, `finished-goods`, `manufacturing-traceability`) following a consistent controller/service/repository layout. Services depend on repository interfaces declared as string token constants (e.g. `BOM_REPOSITORY`, `PRODUCTION_ORDER_REPOSITORY`, `MATERIAL_CONSUMPTION_REPOSITORY`, `TRACEABILITY_REPOSITORY_FOR_CONSUMPTION`, `TRACEABILITY_REPOSITORY_FOR_FGR`, `FGR_REPOSITORY`, `MFG_TRACEABILITY_REPOSITORY`) that are bound in the module's `providers` array to concrete `Drizzle*Repository` implementations under `../infrastructure/repositories/`. Cross-module dependencies flow one-way: `production-orders` imports `boms`, `inventory-transactions`, and `inventory-projections`; `material-consumptions` and `finished-goods` import inventory modules plus the shared `DrizzleManufacturingTraceabilityRepository`; `finished-goods` also rebinds `PRODUCTION_ORDER_REPOSITORY`. DTOs live in per-module `dtos.ts` files using `class-validator` decorators for request validation. Domain-specific exception filters (`BomExceptionFilter`, `ProductionOrderExceptionFilter`) catch domain errors from the shared `@ananya/manufacturing` package and translate them into standardized `{ statusCode, error, message }` JSON responses with appropriate HTTP status codes.
