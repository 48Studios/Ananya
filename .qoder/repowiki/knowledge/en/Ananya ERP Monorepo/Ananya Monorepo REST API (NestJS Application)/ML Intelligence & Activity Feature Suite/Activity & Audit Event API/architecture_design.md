Standard NestJS feature layout: `activity.module.ts` wires `ActivityController` and `ActivityService`, exporting the service for other modules. The controller (`activity.controller.ts`) declares five routes under `/activity`: POST for creating an event, GET for listing with filters, GET `/audit` for security audit logs, GET `/entity/:type/:id` scoped by entity, and GET `/user/:id` scoped by user. All persistence is done directly in the service via the shared `@ananya/database` Drizzle client against the `activityEvents` and `securityAuditLogs` tables — there is no repository layer. Request payloads are validated through class-validator DTOs defined in `dtos.ts` (`CreateActivityEventDto`, `QueryActivityEventsDto`). Dependency direction is one-way: controller → service → database schema/query helpers; the module itself has no external providers or configuration.
