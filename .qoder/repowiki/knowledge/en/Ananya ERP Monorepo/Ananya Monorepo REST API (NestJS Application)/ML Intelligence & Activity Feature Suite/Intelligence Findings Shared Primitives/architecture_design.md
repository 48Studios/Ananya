The module is a flat leaf package exposing three independent concern areas through `index.ts`:

- `finding-fingerprint.ts`: deterministic serialization (`stableStringify`) plus SHA-256 fingerprinting (`buildIntelligenceFingerprint`) and pair canonicalization (`canonicalizePair`). It is the single source of truth for finding identity so every domain derives stable hashes from the same normalization rules (sorted keys, Date→ISO, non-finite numbers→null, circular-ref refusal).
- `finding-lifecycle.ts`: the shared status/decision/feedback vocabulary (`INTELLIGENCE_FINDING_STATUSES`, `INTELLIGENCE_FINDING_DECISIONS`, `INTELLIGENCE_FEEDBACK_ACTIONS`) and transition rules (`canDecide`, `decidableStatusesFor`, `mapDecisionToFeedbackAction`). Terminal states accept no further decision; STALE can only be REJECTED or DISMISSED.
- `apply-timeout.ts`: transaction-local PostgreSQL bounds via `SET LOCAL set_config(...)` on `lock_timeout` and `statement_timeout`. Each calling domain supplies an `ApplyTimeoutScope` (env var names, defaults, error class) while the module only handles the mechanism — SQLSTATE classification against `TIMEOUT_SQLSTATE_CODES` (`55P03`, `57014`), depth-limited Drizzle `cause` walking, and returning a plain `ApplyTimeoutDescriptor` rather than throwing, so each domain wraps it in its own conflict-reason type.

Dependency direction is one-way: this module imports only Node's `crypto` and `@ananya/database` (executor + sql tag). It has no knowledge of components, attributes, or any other subject domain, and deliberately owns no tables, DTOs, repositories, or services — those stay in the owning domains that import these rules to prevent drift between queues.
