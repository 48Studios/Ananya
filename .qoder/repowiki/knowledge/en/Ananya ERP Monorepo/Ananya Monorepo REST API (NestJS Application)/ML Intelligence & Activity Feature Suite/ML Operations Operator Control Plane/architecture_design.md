Four-file NestJS module following a thin controller → service → repository layering:
- `ml-ops.controller.ts` exposes `/ml/ops/*` endpoints (health, overview, models, datasets, usage, training-runs, deploy, rollback, reload), all guarded by `MlAdminGuard` from `../../auth/ml-permissions`. The controller is stateless: it extracts actor identity from `req.user`, validates request bodies via empty DTOs plus an `assertNoRequestFields` helper, and delegates to the service.
- `ml-ops.service.ts` (`MlOpsService`) orchestrates three collaborators: `MlClientService` (HTTP calls into the external ML sidecar), `MlOpsRepository` (database access), and `SecurityAuditService` (audit logging under category `Inventory`). It owns the training-run state machine (`QUEUED → RUNNING → EVALUATING → PASSED|REJECTED|FAILED|CANCELLED`), reconciliation of active runs against the ML service, promotion gates, and audit recording. A custom `MlOpsConflictError` extends `ConflictException` with a machine-readable `reason` field so the dashboard can explain refusals without parsing prose.
- `ml-ops.repository.ts` (`MlOpsRepository`) is persistence-only: it uses `@ananya/database` drizzle schema/query builders against `mlTrainingRuns` and `mlModelDeployments` (plus `aiSuggestionFeedback`, `attributeIntelligenceFindings`, `componentIntelligenceFindings` for usage aggregates). The single-active-run guarantee is enforced by a database partial unique index; duplicate inserts are translated into `ActiveTrainingRunExistsError`. `finishTrainingRunIfActive` applies status transitions only while the run is still active, preventing concurrent readers from overwriting terminal states.
- `ml-ops.dtos.ts` centralises every enum as `as const` tuples (`TRAINING_RUN_STATUSES`, `DEPLOYMENT_STATUSES`, `ML_OPS_REFUSAL_REASONS`, …) plus query/response interfaces. Query DTOs use class-validator decorators; response types are plain interfaces — read models have no decorators.

Dependency direction is strictly controller → service → (repository + ml-client + security-audit); nothing in this module imports back into auth or other controllers.
