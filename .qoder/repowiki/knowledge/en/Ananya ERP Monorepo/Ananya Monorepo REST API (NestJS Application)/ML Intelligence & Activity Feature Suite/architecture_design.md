The `ml.module.ts` is the single NestJS root that imports and re-exports all sub-feature providers: attribute-findings, component-consolidation, intelligence-findings primitives, documentation/component specification intelligence, and ml-ops. Cross-cutting concerns are centralized here — `AuthModule`, `PermissionsModule`, `SecurityAuditModule`, `DocumentsModule`, and a forward-referenced `DataPacksModule` are imported once so every child feature (review queues, consolidation engine, ops control plane) shares the same permission guards (`ComponentWriteGuard`, `AttributeRead/WriteGuard`, `MlAdminGuard`) and audit sink. The `activity` sibling module is imported by `MlModule` and exposed via `ActivityService`, which children call to record user actions alongside ML events; it remains a leaf NestJS module with its own controller/service pair. Children communicate through service-to-service injection rather than direct HTTP calls, and the module's `exports` array defines the stable contract surface that other app modules consume.
