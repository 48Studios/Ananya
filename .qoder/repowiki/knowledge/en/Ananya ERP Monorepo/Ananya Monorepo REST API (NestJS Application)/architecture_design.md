The `AppModule` at `src/app.module.ts` is the single composition root that imports every domain feature module (auth, components/catalog, manufacturing, procurement, inventory/warehouse, sales/crm, accounting/finance, projects/services, planning/scheduling, reporting, search/import-export, ML attributes, documents/storage, notifications/settings, locations/units/manufacturers) plus shared infrastructure (`DatabaseModule`, `SecurityAuditModule`, `ActivityModule`). Feature modules are intentionally thin: each exposes a NestJS `@Module` with a controller, service, and DTOs, delegating persistence to per-domain Drizzle repositories under `src/infrastructure/repositories/` that implement interfaces from sibling workspace packages (`@ananya/inventory`, `@ananya/procurement`, `@ananya/manufacturing`, `@ananya/sales`, `@ananya/finance`, `@ananya/projects`, `@ananya/service`, `@ananya/mrp`, `@ananya/database`). Cross-cutting concerns—session-based authentication, role/permission guards, Postgres error handling, HTTP logging—are provided by the `auth`, `security-audit`, and `common` directories and consumed uniformly by all feature modules. Two entry points exist: `main.ts` boots the Express server and `worker.ts` runs background jobs; both share the same module graph. E2E tests live under `test/integration/` against a real DB fixture.
