Two sibling NestJS feature modules share this scope:

- `search/` — A single `SearchController` (`GET /search?q&limit`) delegates to `SearchService`, which holds an array of `ISearchProvider` implementations under `providers/` (Inventory, Procurement, Manufacturing, Projects, Administration). Each provider implements the shared `ISearchProvider` interface from `search.types.ts`, returning `SearchResultItem[]` with a fixed shape (`id`, `type`, `category`, `title`, `subtitle`, `status`, `href`, `iconName`). `SearchService.search` fans out in parallel via `Promise.all` and flattens results, swallowing per-provider errors so one failing provider does not break the whole query.

- `import-export/` — `ImportExportModule` imports all owning domain modules (`AttributesModule`, `BOMsModule`, `CategoriesModule`, `ComponentsModule` via `forwardRef`, `LocationsModule`, etc.) because bulk mutations must go through each module's own service to preserve business rules; circular dependencies between Components → Ml → DataPacks → ImportExport are broken with `forwardRef`. `ImportExportController` exposes template download (`/template/:entityType/{csv,xlsx}`), file upload endpoints (`/import/preview`, `/import/execute` using `FileInterceptor('file')`), export (`/export`), and job management (`/jobs`, `/jobs/:id/reverse`). `ImportExportService` is a large orchestrator that parses JSON/CSV, validates rows against `ImporterDefinition`s from `importer-registry.ts`, preloads lookup tables into Maps, then dispatches entity-specific insert/update branches inside `executeImport`. `BulkActionService` is a thin orchestration layer: it validates actions via `bulk-action-registry.ts`, enforces a per-request ID cap (`MAX_BULK_ACTION_IDS`), and routes each `(entityType, action, id)` tuple to the owning service's delete/update methods, classifying failures as `SKIPPED` (domain/refusal) vs `FAILED` (unexpected).

Dependency direction is strictly inward: controllers depend on services; services depend on domain services or raw `@ananya/database` schema/query builders; providers depend only on the database schema. No cross-import between `search/` and `import-export/`.
