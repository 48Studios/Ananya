Three-file NestJS feature module: `reporting.module.ts` registers the controller and service; `reporting.controller.ts` declares eight GET routes under `/reporting` (`overview`, `inventory-summary`, `procurement-summary`, `manufacturing-summary`, `project-summary`, `transaction-summary`, `financial-summary`, `cash-flow-forecast`) that delegate directly to `reporting.service.ts`. The service is a pure data layer — it imports table schemas and query helpers from `@ananya/database` (`db`, `and`, `count`, `eq`, `gte`, `inArray`, `sql`) and returns plain DTO-like objects with no business logic. Dependency direction is one-way: controller → service → database schema/query layer. The module also exports `ReportingService` so other modules can consume the same metrics programmatically.
