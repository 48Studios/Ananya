Each subdirectory is an independent NestJS `@Module` (controller + service + module + tokens/dtos) that follows a consistent layering: controllers handle HTTP, services encapsulate business logic, and repositories are injected via `Symbol`-based tokens (`*.tokens.ts`) bound to Drizzle implementations under `../infrastructure/repositories/drizzle-*.repository`. Modules compose dependencies by importing sibling feature modules rather than reaching into infrastructure directly — e.g. `ReservationsModule` imports `InventoryProjectionsModule`, `StockCountsModule` and `WarehouseTransfersModule` import both `InventoryTransactionsModule` and `InventoryProjectionsModule`, and `CycleCountsModule` imports `StockAdjustmentsModule`. The `barcodes/` module is an exception: it bypasses the repository pattern and queries `@ananya/database` tables (`components`, `locations`, `purchaseOrders`, `productionOrders`, `projects`, `inventoryProjections`) directly, implementing a multi-entity QR-code resolver with a `ANANYA:V1:TYPE:ID` payload format. Domain-specific validation DTOs live in per-module `dtos.ts` or `create-*.dto.ts` files using class-validator decorators, and domain-specific error handling is centralized in per-feature `*-exception.filter.ts` files (reservations, stock-adjustments, cycle-counts, warehouse-transfers).
