Three parallel NestJS feature modules (`locations`, `units`, `manufacturers`) each follow the same internal layout: a `*.controller.ts` (HTTP layer), a `*.service.ts` (orchestrator that instantiates `Create*`/`Update*`/`Delete*` use-case classes from `@ananya/inventory`), a `*.module.ts` wiring the controller/service and binding a concrete `DrizzleLocationRepository`/`DrizzleUnitRepository`/`DrizzleManufacturerRepository` via an injection token declared in `*.tokens.ts`, plus per-resource DTOs and exception filters. The service is the only boundary into `@ananya/inventory`; controllers never touch repositories or domain types directly beyond request/response shaping. Each module exports its service so other features can depend on it without leaking repository details.
