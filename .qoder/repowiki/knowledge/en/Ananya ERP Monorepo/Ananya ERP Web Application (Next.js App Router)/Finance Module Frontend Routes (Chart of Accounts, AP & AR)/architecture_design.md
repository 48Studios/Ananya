Three Next.js App Router route segments under `apps/web/app/` — `accounts/`, `accounts-payable/`, `accounts-receivable/` — each exporting a default `'use client'` React component. Data fetching is done in-page via `financeApi` from `@/lib/api/finance-api` (`getAccounts`, `getPayableInvoices`, `getReceivableInvoices`) inside `useEffect`, with local `useState` for data/loading/error. UI composition is uniform across list pages: `PageHeader` + three `StatCard` KPIs + an `EntityDataTable` driven by a `ColumnDef[]` array; the detail route `accounts/[id]/page.tsx` renders a static ledger-account view using `formatCurrency`/`formatDate` from `@/lib/utils`. There is no shared page component — each route is self-contained, depending only on shared `@/components/ui/*` primitives and the `financeApi` client.
