The app is split by Next.js App Router conventions: `app/<domain>/[id]/page.tsx` files are client pages that compose reusable React components from `components/` and call the authenticated API via `lib/api-client.ts` (with per-domain wrappers under `lib/api/`). Cross-cutting concerns live in `lib/` (formatters, attribute intelligence, scanner, ML ops, navigation) and `components/ui/` (shadcn/Base-UI primitives). Domain routes (finance, manufacturing, procurement, sales, warehouse, inventory, CRM, service, master data, projects/tasks, maintenance, reports/intelligence, data operations, settings/security, auth/onboarding) are peers — they share no code between each other and depend only on the shared `components/` and `lib/` layers. The root `layout.tsx` provides the dashboard chrome; `middleware.ts` gates routes; `next.config.mjs` builds to a standalone output with an unoptimized image pipeline and a cache-busting `/sw.js` for the PWA. Tests under `lib/*.spec.ts` use Vitest against the pure helpers, while component tests sit beside their forms.
