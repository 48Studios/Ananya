Each subdirectory under `apps/web/components/` exposes a single React form component (`PurchaseOrderForm`, `PurchaseInvoiceForm`, `GoodsReceiptForm`, `SupplierReturnForm`) that is rendered inside a `DialogShellBody`/`DialogShellFooter` dialog. Forms are stateless UI shells: they own local loading/error state, fetch master data (suppliers, components, locations, POs) via `@/lib/api/*` modules in `useEffect`, and submit payloads through the corresponding API module's `create`/`update` methods, surfacing results via `onSuccess`/`onCancel` callbacks. Line-item-heavy forms (PO, invoice, GR) use `react-hook-form`'s `useFieldArray` with per-line Zod schemas (`poLineSchema`, `purchaseInvoiceLineSchema`, `grLineSchema`) to validate dynamic rows; simpler forms (supplier return) use flat schemas. Cross-entity relationships are enforced at the UI level — e.g., selecting a PO auto-fills invoice lines, selecting a PO populates GR lines from outstanding quantities, and supplier selection filters downstream PO/GR options. The module has no shared internal library; cross-cutting helpers live alongside their form (e.g., `supplier-return-lines.helpers.ts`).
