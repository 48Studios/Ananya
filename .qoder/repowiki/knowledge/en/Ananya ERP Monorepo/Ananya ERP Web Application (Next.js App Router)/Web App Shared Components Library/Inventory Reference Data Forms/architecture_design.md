Each subdirectory under `apps/web/components/` holds a single domain entity with one or more form components. The four simple entities (units, locations, suppliers, manufacturers) each expose a `<XxxForm>` component that is self-contained: it defines a Zod schema, wires it via `react-hook-form` + `zodResolver`, renders fields inside `DialogShellBody`/`DialogShellFooter`, and dispatches to the corresponding `@/lib/api/<entity>-api` client (`create` / `update`) on submit, surfacing errors through a local `serverError` state. Categories split into two files: `category-form.tsx` follows the same pattern as the others, while `category-attributes-manager.tsx` is a richer manager that owns its own data fetching (`attributesApi.getByCategory`, `suggestCategoryAttribute`, `assignCategoryAttribute`), AI-suggestion UI, and nested assign/unassign dialogs. All components are `"use client"` Next.js server components rendered inside dialog shells provided by `@/components/ui/dialog-shell`; they depend only on shared UI primitives (`Button`, `Input`, `Select`, `SearchableSelect`, `Field`/`FieldLabel`/`FieldError`) and never import from sibling form modules, keeping each entity isolated.
