Two sibling sub-packages under `apps/web/components/` with a clear responsibility split:

- `components/` — Component lifecycle and intelligence surfaces: `component-form.tsx` is the central form orchestrator (react-hook-form + zod schema), delegating AI-driven specification rendering to `attribute-suggestions-panel.tsx` and `ai-suggestion-review-card.tsx`, while `component-consolidation-execution-flow.tsx` / `component-consolidation-preview-panel.tsx` implement the two-step confirmation flow for merging duplicate components via `componentReviewQueueApi.consolidateComponent`. Review workflows are surfaced through `component-review-*` dialogs (`queue-dialog`, `finding-dialog`, `duplicate-investigation`, `apply-dialog`) and `manage-component-specifications-dialog.tsx`.
- `attributes/` — Attribute definition CRUD: `attribute-form-dialog.tsx` drives create/update of `AttributeDefinitionDto` with AI-assisted config suggestion and duplicate detection; `attribute-categories-dialog.tsx`, `attribute-options-dialog.tsx`, and `attribute-review-queue-dialog.tsx` support category binding, option management, and review queues.

Dependency direction is one-way outward: these components import typed DTOs and mutation helpers from `@/lib/api/*` (`components-api`, `attributes-api`, `categories-api`, `manufacturers-api`, `units-api`, `ml-api`, `component-review-queue-api`) and pure logic from `@/lib/attribute-suggestions` and `@/lib/attribute-value-equivalence`; they never import from each other except `component-form` → `attribute-suggestions-panel`. All state is local React state — no shared store or server state layer lives here.
