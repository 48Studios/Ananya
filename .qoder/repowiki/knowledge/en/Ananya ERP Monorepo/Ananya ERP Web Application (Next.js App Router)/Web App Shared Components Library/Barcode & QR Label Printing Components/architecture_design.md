The module is split into two layers. The `templates/` subdirectory defines one React component per physical sticker face (Standard, Compact, Detailed, Shelf Bin, and three QR-only sizes), each fixed to a millimetre-precise box size and composed from shared `barcode-viewer.tsx` and `qr-code-viewer.tsx` renderers. A central `templates/registry.ts` declares the `LabelTemplate` union type plus `TEMPLATE_OPTIONS`, `QR_ONLY_TEMPLATES`, and `isQrOnlyTemplate`, acting as the single source of truth so adding a template requires registering it in the type and picker map. `templates/index.ts` re-exports every template's props and component, and `label-preview.tsx` is the dispatcher that resolves an organisation name once and renders the matching template component based on the selected `LabelTemplate`. Above the templates sit three dialog-level consumers: `print-label-dialog.tsx` (single-entity print), `batch-print-dialog.tsx` (multi-entity queue with copies), and `scanned-entity-modal.tsx` (post-scan result view that nests a `PrintLabelDialog`). Both dialogs fetch label payloads via `@/lib/api/barcodes-api`, render a live `LabelPreview` inside a `useRef`-backed container, and hand the resulting DOM nodes to `printLabelDocument` from `@/lib/print/print-document` so the printed sheet is exactly what was reviewed on screen. All UI chrome uses shared primitives from `@/components/ui/*` (`DialogShell`, `Select`, `Button`, `Field`).
