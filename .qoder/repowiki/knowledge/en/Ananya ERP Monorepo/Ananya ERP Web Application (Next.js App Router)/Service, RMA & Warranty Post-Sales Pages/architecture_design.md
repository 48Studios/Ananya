Three sibling Next.js App Router route groups under `apps/web/app/` — `service/`, `rma/`, `warranty/` — each rendered as a React client component (`"use client"`). The `service` group adds a nested `[id]/page.tsx` detail route that reads the id via `next/navigation`'s `useParams`. Each page owns local state for its entity collection, loading flag, and form-dialog visibility; it fetches data through a dedicated API module in `@/lib/api/*-requests-api` (e.g. `serviceRequestsApi`, `rmaRequestsApi`, `warrantyClaimsApi`) and renders the list via the shared `EntityDataTable` + `StatusBadge` + `StatCard` primitives from `@/components/ui`. Create flows are implemented by opening a `DialogShell` that mounts a domain-specific form component from `@/components/{domain}/*-request-form` (e.g. `ServiceRequestForm`, `RmaRequestForm`, `WarrantyClaimForm`); on success the dialog closes and the list is refetched. There is no internal routing or state sharing between the three domains — they are independent leaf pages depending only on shared UI primitives and their own API clients.
