Three sibling Next.js App Router route segments under `apps/web/app/`, each exporting a default `'use client'` React component:
- `categories/page.tsx` — list view with create/edit/delete via `DialogShell` + `CategoryForm`, plus an `EntityDataTable` column layout; `categories/[id]/page.tsx` is the detail view that resolves parent/children via parallel `Promise.all` calls to `categoriesApi` and `componentsApi`, renders hierarchy, bound attributes through `CategoryAttributesManager`, and associated components via `DetailTable`.
- `attributes/page.tsx` — attribute-definition list exposing four sub-dialogs (`AttributeFormDialog`, `AttributeOptionsDialog`, `AttributeCategoriesDialog`, `AttributeReviewQueueDialog`) and integrates the intelligence review queue via `attributeReviewQueueApi.listFindings`.
- `units/page.tsx` — UOM list with base-vs-derived classification.

Dependency direction: pages own all state (loading/error/toast/alert) and call typed API clients from `@/lib/api/*` (`categories-api`, `attributes-api`, `units-api`, `components-api`, `attribute-review-queue-api`). UI composition is delegated to shared primitives in `@/components/ui/*` (`PageHeader`, `StatCard`, `EntityDataTable`, `ConfirmDialog`, `DialogShell`, `RecordStatusBadge`) and per-entity form/dialog components under `@/components/categories|attributes|units`. There is no cross-page state or Redux store — data flows top-down from page-level `useState` into child forms and tables.
