Three Next.js App Router route segments under `apps/web/app/` — `manufacturing/page.tsx`, `boms/page.tsx` + `boms/[id]/page.tsx`, and `production-orders/page.tsx` — each declared as a client component (`"use client"`) and composed from shared UI primitives in `@/components/ui` (PageHeader, StatCard, EntityDataTable, DialogShell, ConfirmDialog, StatusBadge). Data is fetched on the client via typed API clients in `@/lib/api` (`work-orders-api`, `boms-api`, `components-api`) using `React.useEffect` / `useCallback` patterns; lists are cached in local React state and rendered through a generic `EntityDataTable` configured with `ColumnDef<Dto>` arrays. The BOM detail page (`[id]`) adds a revision history sidebar, status-driven action buttons (Draft → Release → Obsolete), and confirmation dialogs for destructive mutations. Cross-entity lookups (e.g., BOM lines to Component names) are materialized into in-memory maps keyed by id to avoid repeated API calls. Forms live in sibling feature folders (`@/components/boms/bom-form`, `@/components/work-orders/work-order-form`) and are opened inside `DialogShell` modals, keeping routes focused on list/detail presentation and mutation orchestration.
