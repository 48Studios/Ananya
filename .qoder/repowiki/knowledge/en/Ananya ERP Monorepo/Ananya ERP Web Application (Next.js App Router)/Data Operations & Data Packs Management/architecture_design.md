Three Next.js App Router route segments, each exporting a default client component (`"use client"`) that owns its own UI state and calls backend APIs via typed API clients in `@/lib/api`.
- `data-operations/page.tsx` is the primary page: it fetches `ImportExportJobDto[]` from `importExportApi`, renders them in an `EntityDataTable` (TanStack Table) with column-based filters (job type, status, entity), and provides per-row actions — inspect details/logs in a `DialogShell` and reverse-import via `reverseImport(id)` to transition jobs to `REVERSED`. It also hosts a global `ImportWizard` dialog triggered from the header.
- `import-history/page.tsx` is a thin re-export alias pointing to `../data-operations/page`, giving two routes to the same feature.
- `data-packs/page.tsx` is independent: it loads `DataPackCatalogDto[]` from `dataPacksApi.getCatalog()`, lets users filter by category and search, and installs packs via `installPack(id)` while keeping a local `installedPacks` set synced against server state. An inspection dialog calls `getPackById` and renders tabs over `attributeDefinitions`, `categories`, `units`, and `rows` from `DataPackDetailDto`.
Dependency direction is one-way: pages depend on shared UI primitives (`PageHeader`, `StatCard`, `Button`, `DialogShell`, `EntityDataTable`) and on `@/lib/api/*` modules; there is no cross-page communication between these three routes.
