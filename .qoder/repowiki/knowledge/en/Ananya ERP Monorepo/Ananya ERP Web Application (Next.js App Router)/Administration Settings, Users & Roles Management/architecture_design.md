Three Next.js App Router route groups under `apps/web/app/` expose admin UIs: `settings/page.tsx` is a tabbed client component (organization profile, system defaults, numbering series, feature flags, danger zone) that fetches data via `@/lib/api/settings-api` and renders shared editors (`NumberingSeriesEditor`, `FeatureFlagTable`); `settings/security/page.tsx` displays immutable security audit events through `auditApi.getLogs` with category filtering. The `users/` group provides a list page (`page.tsx`) with create/edit dialogs and per-user detail (`[id]/page.tsx`) showing effective permissions and audit history; the `roles/` group mirrors this pattern for RBAC with a permission matrix dialog and assigned-users view on `[id]/page.tsx`. All pages are `"use client"` React components that coordinate loading/error/success states via local state, call backend APIs from `@/lib/api/*`, and gate sensitive actions with `PermissionGuard` from `@/lib/auth/auth-context` using string permission codes like `Administration.Settings`, `Administration.Users`, `Administration.Roles`. Data fetching uses parallel `Promise.all` calls and `React.useCallback`-wrapped `loadData` functions triggered by `useEffect`, while UI state is kept in component scope with no global store.
