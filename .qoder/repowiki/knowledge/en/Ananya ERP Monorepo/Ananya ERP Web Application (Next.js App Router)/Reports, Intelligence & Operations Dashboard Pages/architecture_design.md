Three sibling Next.js App Router route groups under `apps/web/app/`, all declared as `'use client'` React Server Components turned client components:
- `reports/page.tsx` is a hub page listing five sub-report modules (`inventory`, `procurement`, `manufacturing`, `projects`, `transactions`) via a `REPORT_SECTIONS` config array; each sub-page follows the same shape — summary KPIs + bar/donut charts from `@/components/charts/*` + an `EntityDataTable` of domain entities with drill-down `<Link>`s to their detail routes.
- `intelligence/page.tsx` is the ML Ops control plane: it owns tab state (`overview | models | runs | datasets | usage`), polls `mlOpsApi` only while `shouldPoll(latestRun)` returns true (using `ML_OPS_POLL_INTERVAL_MS`), and delegates panel rendering to `@/components/ml-ops/ml-ops-panels` (`MlOverviewPanel`, `MlModelsPanel`, `MlRunsPanel`, `MlRunDetailPanel`, `MlDatasetsPanel`, `MlUsagePanel`, `MlActiveRunPanel`, `MlOpsConfirmations`). Access is gated by `PermissionGuard` wrapping the whole tree with `ML_OPS_PERMISSION`.
- `dashboard/page.tsx` is the operations control center: it loads layout + favorites from `preferencesApi`, then aggregates summaries from `reportingApi` plus live queues from `purchaseOrdersApi`, `workOrdersApi`, `stockAdjustmentsApi`, `notificationsApi`, and `activityApi` in one `Promise.allSettled` call. Widgets are rendered through `DashboardGrid` driven by a persisted `DashboardWidgetConfig[]` layout, with a `WidgetPicker` for toggling visibility.

Dependency direction is strictly inward toward shared UI primitives (`@/components/ui/*`, `@/components/charts/*`, `@/components/dashboard/*`, `@/components/ml-ops/*`) and outward-only API clients under `@/lib/api/*`; no cross-imports exist between the three route groups.
