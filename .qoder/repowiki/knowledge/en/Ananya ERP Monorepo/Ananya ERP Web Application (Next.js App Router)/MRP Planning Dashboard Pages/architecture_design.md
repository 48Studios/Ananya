Each route under `apps/web/app/mrp/` is a standalone React Server Component page marked with `'use client'`, following Next.js App Router conventions. The root `/mrp/page.tsx` serves as the MRP hub: it fetches gross requirements via `mrpApi.getGrossRequirements()`, renders summary `StatCard`s, and exposes an action to trigger `mrpApi.executeRun()` which computes demand and displays a transient banner. Sub-pages (`production`, `capacity`, `materials`, `purchases`) each independently fetch their respective DTOs from `@/lib/api/mrp-api` (e.g. `getProductionRecommendations`) and present them through a shared `EntityDataTable` with typed `ColumnDef<...>` arrays. The dynamic route `runs/[id]/page.tsx` loads both the run record (`mrpApi.getRunById`) and its associated planning messages (`planningMessagesApi.getAll(runId)`) in parallel using `Promise.all`, then renders a detail view with severity-filtered log rows. All pages compose shared UI primitives from `@/components/ui` (`PageHeader`, `StatCard`, `EntityDataTable`, `Button`) and rely on `@/lib/utils` for formatting (e.g. `formatDate`). There is no shared layout or state between pages — data fetching and rendering are fully self-contained per route.
