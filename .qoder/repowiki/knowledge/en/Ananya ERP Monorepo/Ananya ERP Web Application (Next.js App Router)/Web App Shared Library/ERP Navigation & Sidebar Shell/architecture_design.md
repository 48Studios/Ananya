The module is organized around a data-driven navigation model: `types.ts` defines the shape of `NavigationModule`, `SidebarSection`, `NavigationItem`, `QuickStat`, and `QuickAction`; `navigation-config.tsx` exports a static `navigationModules` array (Dashboard, Inventory, Procurement, Manufacturing, Projects, Analytics, Administration) plus a `getModuleForPath` matcher that resolves the active module from Next.js pathname. `navigation-context.tsx` wraps the app in a `NavigationProvider` that owns all UI state (`currentModuleId`, `activePath`, `isSidebarCollapsed`, `expandedAccordions`, `pinnedItems`, `recentItems`, `isMobileOpen`, `searchOpen`) via React state, persists collapsed/accordion/pinned/recent settings to `localStorage` under `ananya_*` keys, auto-expands accordions when a child route matches, tracks recently visited routes (excluding login/setup), and exposes a single `useNavigation()` hook for consumers. The `components/` folder renders the visual shell — `sidebar-item`, `sidebar-section`, `sidebar-accordion`, `sidebar-pinned-items`, `sidebar-favorites-recent`, `sidebar-quick-stats`, `sidebar-quick-actions`, `sidebar-section-header`, `sidebar-flyout`, `context-sidebar`, `mobile-drawer`, `navigation-rail`, `navigation-rail-item`, `top-header`, and a thin re-exported `command-palette`. Layout sizing is centralized in `tokens.ts`, which pairs Tailwind class tokens (`NAV_TOKENS`) with numeric pixel widths (`NAV_WIDTHS_PX`) so CSS and JS stay synchronized; a spec file (`navigation-metrics.spec.ts`) asserts this invariant. Dependency direction flows one-way: components → `navigation-context` → `navigation-config` → `types`, while `tokens.ts` is consumed by every component for consistent sizing.
