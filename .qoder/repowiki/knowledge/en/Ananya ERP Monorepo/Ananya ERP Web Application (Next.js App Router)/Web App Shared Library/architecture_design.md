Children are split by concern rather than layered: `api/` (plus `api-client.ts`) owns all backend calls via one authenticated fetch wrapper that each domain file re-exports; pure-presentation modules (`attribute_utilities`, `component_utilities`, `document_intelligence`, `formatters_utils`, `misc_utilities`) derive UI state from backend payloads without React or DOM dependencies; `navigation/` is the only child that renders shell components consumed by the app. Presentation modules depend on `formatters_utils` for display logic and on `api/` wrappers for data, but never on each other, keeping them independently testable. Each utility module ships a co-located `.spec.ts` alongside its implementation, and the `api/` directory mirrors backend domains one-to-one so new endpoints are added as a single file under both `lib/api/` and the corresponding feature folder.
