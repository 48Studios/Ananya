Two-layer structure inside `apps/web/lib`:
- `api-client.ts` is the single HTTP transport layer. It resolves endpoints against `NEXT_PUBLIC_API_URL`, attaches a Bearer token read from `localStorage`/cookie (`ananya_auth_token`), serializes JSON bodies, parses responses (including binary via `getBlob` and form data via `postFormData`), and centralises error handling through an `ApiError` class plus a global 401 interceptor that clears the token, broadcasts a `SESSION_EXPIRED` event via `BroadcastChannel`, invokes a registered `onUnauthorizedHandler`, and redirects to `/login?expired=true` (preserving the original surface via `sessionExpiredUrl`).
- The `api/` directory contains one file per backend resource (e.g. `auth-api.ts`, `attributes-api.ts`, `warehouses-api.ts`). Each file exports a plain object named after the domain (e.g. `authApi`, `attributesApi`) whose methods are thin wrappers around `apiClient.get/post/put/patch/delete/getBlob`. DTOs and request payloads are declared as TypeScript interfaces in the same file, colocated with the methods that use them.
- Dependency direction is strictly inward: domain modules import only `../api-client`; nothing in `api-client.ts` imports any domain module. This makes the transport reusable by any feature while keeping each domain's URL shape and types isolated.
