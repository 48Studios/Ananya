Organized as a domain package under `src/` with one subdirectory per aggregate: `suppliers`, `purchase-orders`, `goods-receipts`, `supplier-returns`, `purchase-invoices`, and `policies`. Each aggregate exposes an `index.ts` barrel that re-exports its entity class(es), input types, repository interface, error types, and command handlers. Entities are implemented as classes with private constructors and static `create` / `rehydrate` factories; business invariants and status transitions live on the entity methods (e.g. `PurchaseOrder.submit/approve/issue/cancel`). Cross-aggregate orchestration is done via application-level command classes (`CreateGoodsReceipt`, `CreatePurchaseOrder`, `UpdatePurchaseOrder`, etc.) that depend on repository interfaces defined per aggregate and persist through them. The `ThreeWayMatcher` service in `purchase-invoices` coordinates `PurchaseInvoice`, `PurchaseOrder`, and `GoodsReceipt` to validate invoices against PO lines and received quantities. The package depends only on shared primitives from `@ananya/core` (e.g. `ObjectId`) and `@ananya/inventory`, keeping it decoupled from persistence and web layers. Build output is emitted to `dist/` via `tsc -p tsconfig.build.json` and the package is consumed by other workspace packages through the `@ananya/procurement` name.
