Packages are organized as a flat workspace where `@ananya/core` (value objects, error hierarchy) and `@ananya/database` (Drizzle schema, migrations, seed data) form the foundation. Every bounded-context package (`crm`, `finance`, `inventory`, `manufacturing`, `mrp`, `procurement`, `projects`, `sales`, `service`, `warehouse`) depends on `@ananya/core` for shared domain primitives and exposes repository interfaces that abstract persistence; `@ananya/database` centralizes Drizzle schema definitions and migration/seed tooling consumed by runtime apps. Cross-cutting tooling lives in sibling packages `@ananya/typescript-config` and `@ananya/eslint-config`, which all other packages consume via `workspace:*` dev dependencies. The `@ananya/shared` package is a thin re-export entry point used to aggregate cross-context utilities. Domain packages do not depend on each other directly — inter-context communication is intended to go through application-layer services or API boundaries outside this scope.
