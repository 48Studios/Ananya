The package is a pure TypeScript domain layer with no runtime dependencies beyond `@ananya/core` (for `ObjectId`). It is organized as one sub-package per aggregate (`requests`, `work-orders`, `warranty`, `rma`, `maintenance`, `notes`), each following a uniform three-file layout: `<entity>.ts` holds the aggregate class plus its value-object enums/types; `<entity>.repository.ts` declares a repository interface plus a `FindMany<Entity>Options` query-shape; `index.ts` re-exports both. The package root `src/index.ts` is a flat barrel that re-exports every aggregate, making consumers import from `@ananya/service` directly. Repository interfaces are intentionally abstract — they expose CRUD + `generateNext*Number()` sequencing but contain no persistence logic, so implementations live in other packages. State transitions (e.g. `assign`, `diagnose`, `startRepair`, `complete`, `close`, `cancel`) are enforced inside the aggregate classes via guarded methods that throw on illegal status transitions.
