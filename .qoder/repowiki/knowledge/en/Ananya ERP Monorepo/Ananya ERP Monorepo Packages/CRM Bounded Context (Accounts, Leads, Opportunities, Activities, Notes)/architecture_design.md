The package is organized as a DDD-style bounded context under `src/`, with one subdirectory per aggregate (`accounts`, `leads`, `opportunities`, `activities`, `notes`). Each aggregate follows a consistent three-file layout: an entity file defining the aggregate class plus `*Props` interfaces, a repository file declaring a read/write interface (`XRepository`) and optional query options, and an `index.ts` barrel re-exporting both. The package root `src/index.ts` re-exports all five aggregates, making them the public surface of `@ananya/crm`. Aggregates depend only on `@ananya/core` for `ObjectId` generation; there are no cross-aggregate dependencies inside this package, keeping each aggregate isolated. Repository interfaces abstract persistence so implementations can be swapped without touching domain logic. A single Vitest spec at `src/crm.spec.ts` exercises the domain behavior of all aggregates to validate state transitions and invariants.
