Two independent, self-contained Python entry points under `apps/ml/benchmarks/`:

- `document_acquisition_benchmark.py` — spins up an in-process `ThreadingHTTPServer` (`_OriginHandler`) serving generated or user-supplied PDFs over `127.0.0.1`, then drives the real `AutonomousWebCollector` (discovery → download → PDF parse → attribute extraction → `ProductRecord` → persistence) via a dynamically written YAML source registry. Per-stage timing is captured by monkey-patching `ResilientDownloader.download`, `CrawlPolicyManager.wait_for_rate_limit`, `ContentExtractor.read_pdf_text` / `build_pdf_record`, and `AcquisitionStore.save` into a shared `StageProfiler`; it also instruments `datasheet_extractor.process` for attribute-extraction latency. Supports two passes (initial + resume) and writes JSON results.
- `duplicate_benchmark.py` — evaluates the RFC-0057 `duplicate_detector.detect` against 10 hand-authored `TestCase`s (resistor/capacitor electrical-parameter guards, package-size, tolerance, dielectric, alias, canonicalization, packaging-suffix scenarios), comparing its accuracy/latency to a simulated general sentence-transformer baseline implemented as 3-gram character Jaccard similarity with a 0.70 threshold.

Dependency direction: benchmarks import production code from `apps.ml.training.collectors.web.*` and `apps.ml.app.services.*` but are not imported by them; they add themselves to `sys.path` so they can run standalone without installing the package. Results are persisted to `benchmark_results.json`.
