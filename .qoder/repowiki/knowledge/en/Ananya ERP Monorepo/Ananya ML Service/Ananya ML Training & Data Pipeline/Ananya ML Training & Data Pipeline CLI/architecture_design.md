Single-package workspace rooted at `apps/ml/training/` with a command-driven architecture centered on `cli.py`, which registers subcommands (`collect`, `data-*`, `dataset-*`, `train`, `evaluate`, `experiment`) via `argparse` and dispatches to dedicated `cmd_*` functions. The package is organized into layered sub-packages that follow a strict data-flow dependency direction: `collectors/` (web crawl + DB/catalog ingestion) → `processors/` (validation, normalization, deduplication, cross-source analysis) → `generators/` (task-specific dataset generators such as classification, attribute extraction, entity resolution) → `datasets/splitter.py` (deterministic zero-leakage train/val/test splitting) → `trainers/` (scikit-learn candidate trainers) → `evaluation/` (metrics and quality gates). Shared state is centralized in `config/settings.py` plus `config/sources.yaml`, which declares crawl sources declaratively without hard-coded URLs. A Rich-based TUI under `tui/` provides live dashboards and event emission (`emit_event`) used by long-running commands like `collect --continuous`. The module exposes a clean public API through `__init__.py` (`settings`, `detect_device`, `ProductRecord`, `DatasetManifest`, etc.) while keeping production inference isolated in sibling `apps/ml/app/` and the legacy RFC-0058 pipeline in `apps/ml/pipeline/`, bridged only via an optional `--legacy` flag in `cmd_train`.
