The module is organized around a unidirectional event-driven architecture: worker threads emit immutable `TUIEvent` dataclasses (events.py) through an `EventSink` into a `queue.Queue`, which the main thread drains in a ~4 Hz `Rich.Live` loop driven by `TrainerTUI.run_job` (app.py). `TUIState` (state.py) is the single source of truth — it exposes only an `apply_event` method so state mutations are centralized and deterministic. Rendering is fully decoupled via pure functions in panels.py (`render_dashboard`, `render_header`, `render_pipeline`, `render_sources_view`, `render_failures_view`, `render_logs_view`, `render_training_view`) that consume `TUIState` but never mutate it; formatting helpers in formatters.py guarantee no NaN/None rendering, and theme tokens in theme.py centralize colors, symbols, and the Rich `Theme`. A background `KeyboardListener` thread maps stdin keys to `UserCommandEvent`s, and a `TUILogHandler` routes Python logging into the same event stream, keeping the TUI failure isolated from job execution.
