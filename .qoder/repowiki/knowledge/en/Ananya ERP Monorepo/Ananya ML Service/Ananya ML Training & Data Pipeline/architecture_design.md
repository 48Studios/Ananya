Two cooperating sub-packages form a single pipeline: `apps/ml/training/` is the reusable library (collectors → processors → generators → trainers → evaluation, all wired through Pydantic `ProductRecord` schemas and centralized `config/settings.py` paths), while `apps/ml/pipeline/` provides the authoritative RFC-0058 production scripts (`run_training.py`, `train.py`, `evaluate.py`, `deploy.py`, etc.) that orchestrate those libraries in a fixed stage order. The `training/cli.py` (`ananya-ml`) command surface exposes both the new composable workflow (`collect`, `data-*`, `dataset-*`, `train`, `evaluate`, `experiment`) and a `--legacy` mode that delegates to the pipeline scripts. All stages communicate via JSON artifacts on disk under versioned directories in `datasets/raw`, `datasets/training`, and `experiments`, with the TUI package emitting live events consumed by the dashboard. Configuration is shared through `config/sources.yaml` (source registry) and `config/settings.py` (workspace root paths), so collectors, processors, trainers, and evaluators all resolve the same base directories without hard-coded paths.
