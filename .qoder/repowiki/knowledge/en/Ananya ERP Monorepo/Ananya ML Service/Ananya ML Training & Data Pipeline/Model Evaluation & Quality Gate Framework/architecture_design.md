Two-file package under `apps/ml/training/evaluation/` with a clear separation of concerns:
- `metrics.py` is a pure-function metrics library exposing `compute_classification_metrics`, `compute_duplicate_metrics`, `compute_set_relevance_metrics`, and `compute_latency_and_memory`; it depends only on numpy/sklearn and has no side effects.
- `evaluator.py` defines the `ModelEvaluator` class, which orchestrates the full evaluation pipeline: loading an active baseline model via pickle, running predictions, aggregating metrics from `metrics.py`, computing six boolean quality gates (accuracy ≥ 0.70 with ≤5% regression vs baseline; duplicate precision/recall ≥ 0.95 with zero critical false merges; P95 latency ≤ 5 ms; peak RAM ≤ 256 MB; zero unverified provenance), and writing two artifacts — `evaluation_report.json` and `evaluation_summary.md` — into the caller-supplied `output_dir`.
- The `experiments/` sub-package is purely output storage: each run directory (e.g. `dataset-crawl-1790258177-baseline-test/`) holds the pair of report files produced by `ModelEvaluator.evaluate`, making experiment results self-describing and machine-parseable.
- Dependency direction is one-way: `evaluator.py` → `metrics.py`; consumers import `ModelEvaluator` directly. Optional integration points (`..tui.emit_event`, progress callbacks) are wrapped in try/except so evaluation never fails due to UI or progress-layer issues.
