The module is organized around a single abstract contract in `base.py`: every processor subclasses `BaseProcessor`, which defines `process(record) -> (ProductRecord, ProcessingAudit)` and a batch helper `process_batch`. The audit model (`ProcessingAudit`) carries a `ProcessingDisposition` enum with three outcomes — ACCEPTED, QUARANTINED, REJECTED — plus reasons and modified fields. Concrete processors live in sibling files:
- `validation.py` → `DataValidationProcessor` enforces identifier completeness, malformed MPN regexes, provenance status, non-product category filtering, and SI physical sanity bounds (`PHYSICAL_SANITY_BOUNDS`).
- `normalization.py` → `NormalizationProcessor` normalizes text, units (via `normalize_unit_value`), manufacturer aliases (`MANUFACTURER_ALIASES`), packaging suffixes (`strip_packaging_suffix`), and maps vendor categories to the canonical Ananya taxonomy via `CANONICAL_CATEGORIES`, `EXCLUDED_CATEGORIES`, and `GLOBAL_TAXONOMY_MAP`; it also exposes `classify_product_signals` using deterministic regex signal classifiers.
- `deduplication.py` → `DeduplicationProcessor` groups by normalized MPN/SKU and applies a value-guard check (`values_differ_critically`, >1% divergence on shared attributes) before merging.
- `cross_source.py` → `CrossSourceAnalyzer` (not a `BaseProcessor` subclass) performs multi-source linkage: same-MPN across sources, packaging-suffix variants, distributor naming diffs, manufacturer alias detection, category/unit reconciliation, and product-family variant counting.

Dependency direction is one-way: processors import `ProductRecord` from `..schemas.product` and each other only through the public re-exports in `__init__.py`. A deliberate local import inside `normalization._clean_breadcrumb_path` avoids a circular dependency with `collectors.web.extractor`.
