- Each record processor subclasses `BaseProcessor` and implements `process(record) -> Tuple[ProductRecord, ProcessingAudit]`, returning one of the three `ProcessingDisposition` values (ACCEPTED/QUARANTINED/REJECTED) with human-readable reasons.
- Domain knowledge (manufacturer aliases, canonical categories, excluded categories, global taxonomy map, physical sanity bounds, invalid MPN patterns) is declared as module-level constants at the top of their respective files rather than being passed into constructors.
- Batch-oriented logic is exposed as classmethods or separate methods (e.g. `detect_cross_source_conflicts`, `deduplicate`) that group records by a normalized MPN key built with `re.sub(r"[\s\-_\/]", "", ...)`, keeping single-record `process` focused on per-record rules.
- Cross-cutting normalization helpers (`normalize_text`, `normalize_unit_value`, `normalize_manufacturer`, `normalize_category`, `strip_packaging_suffix`, `classify_product_signals`) are exported as plain functions alongside the processor classes so they can be reused by both this module and the collector side.
