Two parallel artifact trees under `apps/ml/training/datasets/`:

- `raw/` is the immutable source-of-truth layer. It holds three content buckets — `documents/` (vendor PDFs/HTML grouped by vendor prefix such as `espressif-systems_`, `mg-chemicals-consumables_`, `pololu-robotics_`, `polymaker-filaments_`, `sdp-si-precision-motion_`, `sparkfun-electronics_`), plus empty `catalogs/`, `datasets/`, and `metadata/` directories reserved for future ingestion; `fixtures.json` at the root defines a canonical product record schema (`sku`, `mpn`, `base_mpn`, `name`, `description`, `manufacturer`, `series_family`, `category`, `domain`, `unit`, typed `attributes[]`, `provenance{source, source_type, source_url, collected_at, verification_status, verification_method}`) used as a reference model for downstream records.
- `training/` is the processed-output layer. Each subdirectory `dataset-crawl-<unix_ts>/` is an immutable snapshot produced by the crawler/splitter, containing `manifest.json` (dataset identity, SHA-256 checksum, split/domain/category counts, `group_key: base_family`, `zero_leakage_verified`, seed/ratios in `metadata`) plus `train.json`, `val.json`, `test.json` (and optionally `quarantined.json`, `unique_records.json`, `cross_source_analysis.json`, `source_health.json`). A `tasks/` subdirectory holds per-task artifacts for later stages.

Dependency direction is one-way: code outside this module reads these JSON files and documents as data; nothing inside the scope imports Python modules. The two trees are linked only by the product records extracted from `raw/documents/` being written into the `training/<snapshot>` splits.
