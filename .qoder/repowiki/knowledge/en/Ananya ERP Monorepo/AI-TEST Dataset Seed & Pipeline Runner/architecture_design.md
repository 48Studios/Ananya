The module is a flat collection of Node ESM scripts sharing a single `lib.mjs` helper layer. `lib.mjs` exposes HTTP helpers (`get/post/put/del`, multipart `upload`), token resolution from `ANANYA_TOKEN` or `/tmp/ai-test-token.env`, PDF generation via macOS `cupsfilter`, and manifest I/O for `manifest.json`. Each script is an independent CLI entry point with no cross-imports between them: `seed.mjs` creates manufacturers → categories → components (with inline attributes) → attribute bindings (including a deliberate `SUSPICIOUS_BINDING` fixture) → documents (generated PDFs/text files); `run-pipelines.mjs` invokes the real ML endpoints (`/ml/components/review-queue/audit`, `/ml/attributes/review-queue/audit`, per-document analyze, component documentation aggregate, consolidation preview) and persists results back into `manifest.pipeline`; `cleanup.mjs` performs a dry-run-by-default deletion pass using both the API (documents, components, bindings, categories in child-first order) and direct `docker exec psql` SQL to purge dependent rows (feedback, activity events, audit logs, intelligence findings); `verify-extraction.mjs` and `report.mjs` are read-only verification/reporting utilities; `dataset.mjs` holds the declarative test data spec consumed by seed. All mutations go through the live HTTP API so DTO validation and domain guards are exercised end-to-end, and every created record ID is recorded in `manifest.json` so cleanup is deterministic and scoped to the `AI-TEST-` namespace.
